# Vector execution dependency preflight — 2026-10-29

No dependency is added or selected. The current exact scalar/vec0 diagnostic misses the provisional event-loop target. Prefer engine-owned transaction/recovery semantics over implementing an ANN publication or rollback protocol ourselves.

- [Vectorlite upstream](https://github.com/1yefuwang1/vectorlite#limitations) explicitly lists unsupported transactions and an in-memory index. It is not a direct fit for EARS units/rollback and persisted generation ownership; no integration is made.
- [libSQL's native vectors](https://docs.turso.tech/features/ai-and-embeddings) put DiskANN indexes in the database engine. This remains a candidate, not a proven drop-in. [Its JS compatibility implementation](https://github.com/tursodatabase/libsql-js/blob/main/compat.js) lacks function registration, used by this branch's trigram regex path. Verify the pinned package, read-only construction, filter-before-near behavior, nested units, failure mapping and packaging before choosing it. Official registry metadata pins stable libsql 0.5.29; it is not a project dependency; a subsequent isolated compatibility probe is recorded below. Main's newer prerelease API is not proof about that stable version.
- [SQLite-Vector 1.1.2](https://github.com/sqliteai/sqlite-vector/tree/1.1.2) can load into the existing binding. The isolated probe below establishes a live-update/rollback integration problem for its quantized preload; no fast-path integration follows.

The official Linux arm64 release archive SHA-256 matched GitHub's published digest 3d5c14db9d83e18cc58240b4c0303435d9b5c6c703636c11df60184be608553c. Extracted vector.so SHA-256 is 3c485977eca0cd52c664b31ccf0a5c80af66ade16b0a2921f1413bac3f4f5668. Only a private temporary artifact was downloaded; no dependency lockfile changed. Probe used offline disposable Linux, read-only original binding seed, 2 CPUs/6 GiB/no extra swap, capabilities dropped and actual mode-denial preflight.

Raw exact scanning observed own writes and rollback. Quantized/preloaded scanning initially answered correctly, but after a committed source update still returned row 1 (the old nearest) while exact scanning returned row 3. Explicit quantization/preload refreshed it. Rebuilding/preloading within a unit, then rolling back, left that handle's preload returning rolled-back row 1; exact scanning and a newly opened handle returned row 3. The probe deliberately exits 2 for these incompatible-without-extra-invalidation checks, with all outcomes in sqlite-vector-probe.json. This is not a claim of corruption in authoritative SQLite data or a violation of an upstream promise to maintain the index automatically. It demonstrates that adoption would require extra ownership/invalidation behavior, which has not been implemented or qualified.

Do not infer high-dimensional recall, speed, OS support or full EARS parity from this four-row dependency probe. Next select a bounded native-engine compatibility probe before choosing a package, and retain any rejected strategy alongside its concrete contract reason.


## Stable libSQL compatibility probe

The stable registry package libsql 0.5.29 was installed with scripts disabled in disposable Linux, separately from the repository and without modifying its lockfile. All three attempts used the same resolved dependency lockfile; subsequent attempts used npm ci. Node 23.11.1, two CPUs/6 GiB/no swap/capability dropping and actual mode denial are recorded. The native addon SHA-256 is 712f59a8f50a2e537afb7cc1cd57013f29e6026f355a9a4bd4716c0eccbe48c5; the embedded engine reports SQLite 3.45.1.

The first probe aborted natively. Persisted stages in the second isolate this to the first ANN query after successful table/inserts/index construction; the log records an Option::unwrap panic, not a catchable refusal. A controlled third attempt changes single-BLOB arguments from stmt.all(buffer) to stmt.all([buffer]) (and the analogous single-BLOB run calls). It completes, implicating binding shape rather than establishing that native ANN cannot execute. No binding patch, package upgrade or production adaptation was made; retain both crashes.

The completed probe confirms JSON/FTS5 and VACUUM INTO with an ANN-readable backup, plus unit rollback/reopen on this four-row fixture. It rejects direct substitution: .function() throws not implemented, and a constructor opened with {readonly:true,fileMustExist:true} accepts a write. ANN top-one results on the updating handle missed the expected tiny-fixture neighbor while another handle found it. That requires independent recall/cache investigation, not a claim of authoritative transactional corruption. The post-filter check happened after that miss and therefore does not qualify filter-before-near semantics. Large-corpus latency, recall, supported packaging, failure mapping and full EARS compatibility are untested.

Next prefer the smallest remaining counterfactual in the existing pinned engine: vec0 int8-derived candidates with original Float32 reranking. Preregister fixed candidate count/quantization, independent recall, read-own-write/savepoint/reopen proofs, both selective scopes and large-k/multiple-chunk behavior before any integration. Quantization must be independently computable per vector so a write does not require full-corpus re-quantization. This is still an execution-strategy question; nothing above relaxes the original goal or approves adoption.
