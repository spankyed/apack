# Single-field projection SQL controls

The matched built-package baseline at 470c12dfdd records four instrumented SQL calls for a field read (plus uninstrumented BEGIN/COMMIT). Authoritative scalar and overflow storage is fetched separately. The candidate change joins the requested overflow field to its inline row for single-field projections. Wider pages keep their existing two-query path. Schema revision, transaction snapshot, caller ordering, entity lookup and watch tracking remain on the same code path; no schema/data cache or identity inference is added.

From repo root, run `node docs/references/evidence/ears-sqlite-implementation-2026-10-28/projection-join-controls/control.mjs`. It executes the actual old/new generated queries through Python's built-in SQLite against the same scratch store. Eight projection shapes agree over absent rows, ordered duplicate IDs, missing/null/inline/overflow/flexible and identity fields; each single-field storage read makes one call. Both projected and full-row reads still refuse duplicate authoritative cells and missing overflow. Scratch storage is removed in finally. These are SQL correctness controls, not better-sqlite3/Node speed or full driver qualification.

Real-driver regressions additionally cover all lossless kinds (including Date, signed zero, bytes, arrays, nested objects and __proto__), independent copies for duplicate owners, read-only reopen, corruption, all fifty page rows, no unrelated-body decoding and scalar patch behavior.
