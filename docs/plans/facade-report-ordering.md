# Stable facade reports across source and build routes

Status: repair implemented and accepted on master; separately owned Claude branch integration remains a handoff.
Created: 2026-10-26.

## Problem and evidence

The Claude Code branch's non-native gate stopped at `facade:check` after a successful
pack build. Source-derived and build-derived reports differed in property and union
ordering. A diagnostic TypeScript AST comparison matched after sorting property
signatures and union alternatives. That diagnostic is evidence about the captured
pair, not a replacement for the official gate or proof that arbitrary sorting is safe.

The affected product delivery is committed through `32eb633b8` on
`session/claude-code-closeout`. Its local failure is preserved under
`node_modules/.cache/apack-chain/runs/2026-10-26T15-13-31Z-62064/facade-check.log`
in that worktree. Detailed evidence is in the research checkout's
`docs/reviews/claude-transport-hardening-2.1.302.json`.

## Current master already does part of the work

Planning baseline: master `dacf05e33`.

- [facade-report.ts](../../packages/apack-cli/src/build/facade-report.ts) shares report
  generation and comparison between the source and verified-build routes. Its
  `comparableReport` already normalizes property-only type literals with unique names.
  It preserves overloads and duplicate-name members.
- [declaration-text.ts](../../packages/apack-cli/src/build/declaration-text.ts) already
  sorts all-literal unions. It deliberately leaves other unions alone.
- [The command](../../packages/apack-cli/src/commands/facade-report.ts) makes
  `--from-build` read-only and validates current sealed build inputs. It refuses
  combining `--from-build` with `--update` or `--skip-generate`.

Reconcile the failing branch with current master before designing another normalizer.
Do not duplicate the property-order comparison that already exists.

## Deliverable and boundaries

Make the source and verified-build facade routes agree for the evidenced ordering
variation while continuing to reject meaningful contract changes. Keep report
generation and comparison consistent through their shared implementation.

Scope is facade report/declaration normalization, focused regression coverage and
derived report updates. Do not change runtime behavior, EARS, pack contracts,
compiler capture/watch behavior, CLI flag meanings or acceptance scope. Do not
manually patch reports, accept stale builds, skip the gate or use the diagnostic
normalizer as an approval bypass.

Implementation was explicitly authorized after this plan was written. The repair is on
master in the main checkout; leave the separately owned Claude Code worktree untouched.

## Implementation sequence

1. **Pin and reconcile the inputs.** Record master and product branch commits and
   preserve existing changes. Determine which ordering repairs the branch already
   contains. Integrate the relevant current master changes through the agreed branch
   workflow, then run the focused facade check against current verified build inputs.
   If existing repairs close the failure, retain that evidence and omit unnecessary
   normalization changes.
2. **Isolate any remaining difference.** Reduce the preserved report pair to a small
   regression fixture. Check optional unions containing `undefined`, nested Zod
   input/output shapes and property ordering. Identify the exact AST forms responsible;
   do not assume every original diff remains on current master.
3. **Implement the narrow shared repair.** Extend existing normalization only for the
   evidenced forms whose reordering preserves the contract. Prefer deterministic
   output from the shared report route where practical. If comparison-only
   normalization remains intentional, keep its rules aligned with generation and
   document why generated bytes may differ. Preserve overload, tuple, intersection,
   duplicate-member and other potentially meaningful order. Do not alphabetize every
   union or declaration member indiscriminately. Preserve comments and readable diffs.
4. **Prove equivalence and sensitivity.** Cover the reduced ordering case, both command
   routes and meaningful mutations: changed property types, optionality, readonly
   modifiers, added/removed union alternatives and overload precedence. Include
   idempotence and meaningful comment-change coverage. Existing stale/missing report,
   changed-input and tampered-build refusals must remain effective.
5. **Regenerate and review.** Use the supported source update command for affected
   reports. Read every diff and separate intended contract changes from ordering-only
   churn. Keep `--from-build` read-only. Commit coherent tooling and report checkpoints.
6. **Close integration acceptance.** Run the affected facade cases first. Once they
   converge, run the required repository gate for the frozen candidate. Reconcile the
   accepted repair back into the Claude Code branch and close its original facade
   failure against those exact inputs.
